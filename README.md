# 喵星旅人_world.execution(cat);

从登陆的第一只猫猫，到登陆月球与探索 Asriel 的静态增量游戏。

采用 **Vue 3 + TypeScript + Vite**：生产、资源、建筑、科技、人口、太空、威望等规则位于纯 TypeScript 模拟层，Vue 负责展示，通过显式 store 与 runtime 连接。无需后端，存档保存在浏览器 localStorage。

## 运行与部署

建议使用支持当前 Vite 的 Node.js 版本（例如 Node.js 22.12+；最近验证环境为 Node.js 24）。

```sh
npm install
npm run dev       # 开发服务器，绑定 0.0.0.0（局域网可访问）
npm run typecheck # TypeScript + Vue 模板检查
npm test          # 模块测试（自动发现）+ 保留 VM 回归
npm test -- save  # 只跑路径含关键字的测试文件
npm run check:fast # typecheck + 模块测试（跳过浏览器与构建）
npm run test:browser
npm run build     # 构建静态网站
npm run preview   # 本地预览构建产物
```

已安装依赖且希望严格按锁文件安装时，可以使用 `npm ci`。

[vite.config.ts](<vite.config.ts>) 使用 `base: './'`，产物可部署在域名根路径或子目录。生产构建目标为 ES2022；不建议通过双击 HTML 文件代替 HTTP 服务运行。

### 存档安全

- 正常运行时按真实经过时间触发约每 10 秒自动保存；设置页提供立即保存、JSON 导出与导入。
- 读取与导入仅接受通过完整校验的 schema 31 存档；schema 12–30 全部拒绝，包括已放弃的 0.6 原型存档。当前同 schema 的有效导入仍受支持，这不是旧档兼容。
- 无法读取、无效或不兼容的本地存档触发 `saveBlocked` 保护，日志提示前往「设置→硬重置」。原始存档保持不动，自动/手动保存与软重置不得覆盖它。沿用原 localStorage 键是为了检测旧数据，而非换键后静默开新档。
- 更换域名、协议、端口或浏览器前先导出存档；不同来源的 localStorage 不共享。
- schema12～30不提供迁移或退役内容清理；不要通过修改版本号尝试转换这些已明确退役的存档。
- 从beta0.6.6起，默认兼容当前支持分支及后续版本的存档。新增字段提供精确升级默认值，新解锁条件不使原有合法进度失效；除非用户明确要求，不再断档。本次修复schema31危险物质库缺失记录和已有撕裂者超频研究的载入。
- 正常存档的软重置与核爆仍沿用传统威望保留规则。硬重置清空所有进度、成就、威望资源与永久升级，创建 schema 31 新档；只有成功写入存储后才退出保护，写入失败仍保持保护。

## 当前功能概览

### 地面经济与人口

- 资源生产、持续消耗、仓储、集装箱、建筑递增价格、科技前置与资源解锁。
- 猫猫岗位、幸福度、人口增长、税收、政府体制、军事训练与核爆威望。军营（+2 士兵上限）可开关：士兵数量不能大于上限，超出上限的士兵立即移除，关停军营会立刻降低上限与幸福度压力（资源不足只暂停训练、不删兵）。
- 士兵拥有**单兵战斗力**与**单兵防御力**两项属性：战斗力决定突袭战力，防御力只降低伤亡（每点使伤亡乘以 1/(1+防御力×0.1)）。两者都由装备科技累加——铁制装备、新型单兵装备、高级热武器、凯夫拉纤维、磁轨炮各提供固定 +1，军政（+20%）与泰坦之力（+5%/级）再放大战斗力。军事页的战斗力与防御力数字可悬停查看全部加成来源。
- 士兵毛皮采集速度与战斗力挂钩：每位士兵 **0.2 × 单兵战斗力^0.5** 毛皮/s。裸装（战斗力 1）仍是 0.2/s，满装（战斗力 5）为 0.447/s；平方根让百分比加成对毛皮的效果减半，也保证士兵采集始终是次线性增长——后期毛皮主力仍是工厂生产线。
- 工作自动分配：总开关控制启停，有限岗位可独立开启并设人数上限（-1不限），右侧拖拽排列优先级；只用空闲人口补缺，不从其他岗位调人。
- 工厂共享生产线；工匠自动锻造与左侧手动锻造，支持倍率操作。
- 资源耗尽后的连续饥饿计时、死亡处理与岗位裁剪。
- 建筑默认不再统一限制为 300 座；有明确上限的建筑仍遵守其上限。
- 每座猫咖提供 1 个名额，直接并入原有艺术家岗位；艺术家总容量来自剧场与猫咖。不再提供旧猫咖岗位存档合并。
- 秘银属于无储量上限的锻造物，**不支持集装箱分配**；不再转换旧秘银集装箱分配。
- 实验室每座提供 **1000** 知识容量；完成「电力」研究后成为耗电建筑，每座请求 **2 电力**，获得供电的实验室单座容量提升至 **2000**，未供电或电力超额时保留基础 1000。猫猫教授基础知识产量 **1/s**，猫猫科学家基础知识产量 **2/s**；数据中心每座提供知识容量 **2500** 与知识产量 **+5%**。

## 粒子与 CRISPR

### 产量软上限

实际粒子数不会被截断；仅**产量加成**转换为有效粒子数。默认参数为软上限 `S = 400`、前段强度 `a = 0.2`、后段尺度 `L = S / 2 = 200`。

```text
P <= S：E(P) = (S/a) × ln(1 + aP/S)
P >  S：E(P) = (S/a) × ln(1+a) + L/(1+a) × ln(1 + (P-S)/L)

普通资源倍率 = 1 + E(P) × 0.005
锻造物倍率   = 1 + E(P) × 0.000625
电力倍率     = 1
```

两段在软上限处数值及斜率连续，不按每 200 个做阶梯取整。400 以下轻微递减，以上递减加速；新增粒子始终增加收益。自动 / 手动锻造共享同一计算。锻造物系数为普通资源的 **1/8**。

**空间推理储量加成不使用有效粒子数**：普通有限容量资源按实际持有粒子数，每粒子 +0.04% 储量，线性计算；锻造物与特殊资源不套用该储量加成。

### 永久升级

CRISPR-16 为特殊层级科技，要求完成基因测序；研究后开放 ARPA 的永久修饰页。七项升级为材料效率、创新材料、结构强化、物理定律、半条命3、基因优化、空间推理。升级消耗实际粒子，软重置与核爆后保留效果，但新周目研究入口仍需要本周目解锁。

T1「基因剪切」（前置基因优化，100粒子+25卡西米尔晶体）在完成本周目基因测序后，于 ARPA-遗传学开放**基因修饰**：花费 20 万知识制造一个 C/G/A/T 碱基（特殊资源II，资源栏单行显示，支持 Ctrl/Shift/Alt 倍率），再用对应碱基升级 8 个基因（价格 10×2^等级）。碱基与基因等级仅本周目有效。

威望资源（粒子、卡西米尔晶体、暗能量、和谐晶体）在首次获得前隐藏，获得过一次后即使数量归零也保持显示。

核爆单次粒子奖励的原有软上限与上述**持有粒子产量软上限**是两个独立规则，不要混用。

**响应式约定**：模拟层是普通可变状态，不依赖 Vue 或 DOM。组件的 computed 读取状态时必须同时读取 `props.revision`；仅返回同一个 state 引用无法使缓存自动失效。操作通过 `store.mutate()` 修改状态；加载、导入与重置由 runtime 统一处理，并刷新版本号。

**规则单一来源**：UI 使用模拟 helper 获取价格、消耗、容量和支持，不重新写一份简化公式。新增建筑 / 科技时检查类型、目录、区域、解锁、初始状态、当前存档完整性、悬浮详情和 legacy bridge。

## 已知边界与后续检查项

这些是当前源码检查得到的限制 / 不一致，记录在此方便继续开发，不把测试通过等同于所有需求已彻底解决：

- 暂停开关当前阻止 live tick，但没有持续重置时钟；恢复时可能补算暂停期间经过的时间。载入存档时不再执行离线模拟。若要求暂停时间彻底不结算，需要补充实现与专门测试。
- “总是启用新建筑”目前明确覆盖月球支持不足的默认停用路径；一般建筑电力 / 全部支持不足时的默认停用行为需要进一步统一。
- ARPA 与普通建筑共享容量及显示栏目，但 ARPA 仍有独立结算器；严格统一 FIFO / 乱序执行顺序需要后续审查。
- 队列估算不模拟未来科技、建筑收益或纪念碑随机材料变化；不应作为精确完成承诺。
- 科研卫星的「科学家知识产量」曾出现悬停写 +1%、实际结算 +2% 的漂移，已在 beta 0.7.5 统一为由 `building-effects.ts` 中 `RESEARCH_SATELLITE_LAB_OUTPUT` / `RESEARCH_SATELLITE_LAB_CAPACITY` 驱动的单一来源；后续调整该平衡值请只改这两个常量。
- Q 快捷键的失焦清理、Shift 与强制入队交互，以及科技树同层前置横向线路，仍值得增加专项验收。
- beta 展示版本、npm 包版本和存档 schema 各自独立；升级展示版本不要直接改 schema，仅在明确调整存档契约时升级 schema；本次 schema 31 是拒绝旧档的断代边界，不是迁移入口。

## 维护原则

优先修改 TypeScript/Vue 源码与真实回归测试；平衡数据以数据目录为准。保持当前 schema 的严格校验与写入保护，不重新引入旧档兼容 helper，也不要把生成 bridge 当作第二套手工规则实现。清理截图、调试或构建文件不应触及浏览器存档；发布前导出备份并完成上述四步验证。
